# S003 preregistered plan — CAM-S003-01 (fixed before any S003 computation)

Date 2026-10-12. This file is hashed (SHA-256 recorded in `evidence/S003/HASHES.md`) **before** any solver in `tools/cam_s003_*` is executed. Any later deviation is listed in the S003 report as a deviation, never silently.

## Model (both sources agree; see `research/S003_SOURCE_RECONCILIATION.md`)
Finite simple labeled graph G, connected; configuration c: V→N, size ||c||; move u⇒v along an edge needs c(u)≥2, sets c(u)-=2, c(v)+=1. Stacked: |supp|=1. Cleared: size 1. stack(G)/clear(G): least t≥2 such that **every** configuration of exact size t is stackable/clearable (clear only for connected non-bipartite G). Almost stacked (AS): ∃v0 ∀u≠v0 c(u)≤1. ASH(G): stack(G)=least t≥2 with every AS configuration of size t stackable; analogously clear for non-bipartite G.

## Mathematical target and success criteria
Headline success: unconditional proof of universal ASH-stack and/or ASH-clear, or a fully certified finite counterexample to either. Everything else is scoped progress.

Planned key reduction (to be proved in full in the report): with n=|V|, **ASH(G) ⇔ for every t with n<t<stack(G) some AS configuration of size t is losing** (same for clear on non-bipartite G). Hence a counterexample is exactly an *AS-gap*: a mass t with n<t<stack(G) at which every AS configuration wins.

Auxiliary conjectures to test on all computed data (a false one gets a smallest counterexample; it is NOT an ASH refutation): (A) AS-loss is downward closed on t>n; (B) AS-loss at t=stack(G)−1; plus any route-A/B/C/D lemma proposed in-session.

## CAM-S003-01 graph classes, bounds and completeness scope
All graphs simple, labeled 0..n−1 with explicit edge lists in code/output; no symmetry quotient (each labeled configuration examined) unless stated.

- **T1 (full layers, general configurations):** C6 (t≤16), C7 (t≤23), C8 (t≤32), C8+chord{0,4}, C8+chords{0,2},{4,6}, S002 triangular ladder with leaves, K2,6 (t≤20), W8 (t≤14 re-check). Each graph: all exact masses t=2..T where T = min(threshold found + 1, per-graph cap). Caps: n=8 t≤40.
- **T2 (complete atlas, n≤6):** every connected simple graph with 1..6 vertices up to isomorphism (self-generated by brute-force canonical form over all n! relabelings; counts must equal 1,1,2,6,21,112), all exact masses up to stack threshold + 1 (and clear threshold + 1 when non-bipartite), cap: layer size ≤ 60M configurations. **T2b (n=7, budget permitting, ≤60 min):** every connected graph on 7 vertices (853) with t ≤ 55 cap; graphs whose threshold exceeds cap reported as cutoff only.
- **T3 (AS-only, stack known unconditionally):** every tree with 2..9 vertices (n=10 budget permitting, ≤10 min per tree), stack(T)=estim(T) taken from the earlier TreeStack theorem (arXiv:2609.31811; Lean `TreeStack.stack_eq_estim_of_two_le_card`), cross-checked against T2 for n≤6. For each t in (n, estim(T)−1] search AS configurations for a complete-reachability losing witness. Also K_n (n=3..8, stack=n+1, April Thm 8.1) and K_{a,b} (stack=3α+1, April Thm 8.2) where in budget.
- **T4 (selected n=9/10, cap):** Petersen graph, wheel W9 (hub 0 + 8-rim), C9+chord{0,4}: all exact masses up to threshold+1 or cap (n=9 t≤30, n=10 t≤25).

Per-layer cap 60M configurations; total wall-clock budget ≤ 3 h on 4 cores/15 GB. Exceeding cap/budget yields an explicitly reported cutoff, never an extrapolation.

## Algorithms (independence)
1. `tools/cam_s003_fwd.c` — forward layered exact DP over all compositions (combinatorial-number-system ranking, bitset per layer, win_t(c) = goal(c) ∨ ∃ legal move to win_{t−1}). Reports per t: total, AS total, losses and AS losses for stack and clear, plus order-free fingerprints of the losing sets.
2. `tools/cam_s003_rev.c` — separately written reverse predecessor propagation (win_t = goal_t ∪ parents(win_{t−1})), different ranking (lexicographic DP table), same fingerprints. Must agree on every layer computed by both.
3. `tools/cam_s003_pyrev.py` — pure-Python set-based reverse fixpoint (generalising S002 reverse checker) on layers ≤ 5M configurations; must agree.
4. `tools/cam_s003_as.c` + `tools/cam_s003_cert.py` — per-configuration exact memo solver for AS checks; every claimed *winning* configuration in a candidate certificate carries an explicit move sequence replayed by the Python checker; every claimed *losing* witness is checked by exhaustive Python BFS of its full reachable set.
Bipartiteness is computed by BFS 2-colouring; clear results for bipartite graphs are not reported as clearing numbers.

## Gap / counterexample protocol
Any t with n<t and (losses>0, AS losses=0) is a CANDIDATE: report labeled adjacency, t, every AS configuration at t with replayed winning sequences, one general losing configuration at t with two independent full-reachability non-stackability (non-clearability) checks. Only then "COMPUTED_EXACT counterexample candidate, Lean pending"; otherwise CANDIDATE ONLY. No claims beyond enumerated cutoffs.
