## What is proved

For the nine-vertex graph `G9` (graph6 `HCQTaXi`, edges 0-3, 0-5, 0-6, 1-4, 1-7, 1-8, 2-6, 2-8, 3-5, 3-6, 4-7, 4-8, 5-7, 6-8), in Lean 4 with Mathlib, from the definitions in `AlmostStacked/Defs.lean` (repeated verbatim in `Challenge.lean`):

- `G9` is connected and not 2-colourable (non-bipartite);
- STACK K1-K4 and CLEAR K1c-K4c: the size-14 non-stackable (non-clearable) configurations are exactly `cStar = (0,0,1,0,0,5,0,8,0)` and its image, neither almost stacked; every configuration of size >= 15 is stackable and clearable; every layer 2..14 has a loser; there is an almost stacked loser of size 13;
- `stack(G9) = clear(G9) = 15` (`IsStackNumber`, `IsClearNumber`), the almost-stacked thresholds are 14, `L_all = 14`, `L_AS = 13`;
- `¬ ASHStarStack G9`, `¬ ASHStarClear G9`, and the universal negations: the critical ASH* fails for some connected graph (STACK) and for some connected non-bipartite graph (CLEAR);
- general lemmas: clearable implies stackable (T1); monotonicity above the order (October Lemma 4.7 / S003 Lemma 2) for graphs without isolated vertices.

The statements of record are the 25 theorems of `Challenge.lean` (listed in `comparator.json`; three of them re-stated with the section universe in S018, finding F1). The earlier TreeStack result `stack(T) = estim(T)` (arXiv:2609.31811) is prior work and is not used or reproved; its Lean package is not reused.

## How

`AlmostStacked/Checker.lean` defines a Boolean layer checker (binary-search-tree order, soundness, candidate completeness = lemma C5, terminal 0/1 vectors) and proves `layer_step`: if the previous tree is exactly the set of codes of losing configurations of size t-1, the checked tree is exactly that set for size t. The certificate data (`AlmostStacked/Data/`, generated by `tools/s017_gen_layers.py`, untrusted) are the claimed losing layers of masses 2..15 for each game. Each layer check is a separate module (`AlmostStacked/G9/Check*.lean`) evaluated by the kernel with `decide +kernel`. No `native_decide`, no `Lean.ofReduceBool`, no custom axiom, no `sorry` outside `Challenge.lean`.

## Building

```
cd formal
lake exe cache get
lake build   # since S019 the heavy checks are import-chained: one at a time
```

Measured costs and the frozen-module ledger: `sessions/S017/LEAN_RECORD.md`, `formal/FROZEN_MODULES.md`. The kernel checks are heavy: each of the larger layer checks takes about 20-80 s and commits up to about 10 GB, and before S019 a plain `lake build` ran them in parallel and could exhaust a 16 GB machine (the staged script tools/s017_staged_build.sh was the workaround); since S019 they are import-chained and a plain build takes about 11 minutes with peak about 10 GB. Hosted CI does not build the Lean project (UNVERIFIED on hosted runners).
