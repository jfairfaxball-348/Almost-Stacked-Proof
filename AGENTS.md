# Binding research and repository rules

1. **Authority:** live remote main SHA, this file, authoritative/START_HERE.md, STATE.json, phase gates, session protocol, then catalogues and evidence. Reconcile conflicting files explicitly.
2. One **numbered research session** per fresh owner invocation; a future handoff is never permission to execute it in the current session. The S001 bootstrap-only scope is historical; the current explicit invocation selects its own numbered session.
3. Headline: prove or disprove the **universal** Almost Stacked Hypothesis in its **exact cited form**, not just a cycle formula or a tree consequence. Separate stack for connected graphs and clear for connected non-bipartite graphs; never conflate them.
4. The pre-existing TreeStack result `stack(T)=estim(T)` (nontrivial trees) is an **earlier result**. Properly credit arXiv:2609.31811 and registered Lean package. No rediscovery or unqualified novelty claim. Check exact estimator/threshold conventions.
5. Primary-source access statuses: METADATA_ONLY, ABSTRACT_INSPECTED, STATEMENT_INSPECTED, PROOF_INSPECTED, SECONDARY_ONLY. A paper's abstract is not the full theorem. Source citations carry stable SRC identifiers; no copyrighted PDF mirrored here without rights.
6. Claim statuses: SOURCE_STATED, PROGRAMME_PROVED, COMPUTED_EXACT, HEURISTIC, FORMALLY_CERTIFIED, INHERITED_UNVERIFIED. A conditional paper theorem, computer observation or Lean theorem in a different repository is not automatically a universal programme proof.
7. Counterexamples require a precise finite graph, labeled adjacency, configuration, threshold, complete reachability/optimality claim as appropriate, two independently written checkers or proof certificates, and later Lean kernel proof and cold re-check. Distinguish a *failed* move sequence from impossibility.
8. Every search is pre-registered with graph/configuration class, size cutoff, bounds, symmetry, independent validator, logs/hashes and explicit completeness scope. No extrapolation from small examples. Symbolic work is encouraged; computational exploration is allowed **only after** a written bounded plan.
9. Proof requires complete lemmas and quantifiers. Check invariants, parity/bipartiteness, `t>=2` conventions, zero and one vertex cases, exact-versus-at-least total-pebble thresholds and legal moves. No `sorry`, `admit`, unreviewed axioms or unexplained `native_decide` in a certified theorem.
10. Stage gates: Phase 0 bootstrap -> Phase 1 mathematics -> Phase 2 first novelty -> Phase 3 Lean -> Phase 4 final comprehensive novelty -> Phase 5 Palomar -> Phase 6 paper/arXiv. Record PASS evidence; owner may authorise a revised plan, never silently advance.
11. Each session uses one branch with one atomic authored session commit, an ordinary PR, and non-force merge if GitHub allows. Pin actual head/parents/merge/re-read main; do not invent SHA, workflow, review, or test results. No auto-merge or force.
12. Full closeout: update state, decisions, failure/session/gate ledgers, source/claim catalogs, proofs/campaigns; prepare one COMPLETE FUTURE handoff unless a genuine owner-action blocker precludes it. No contact with authors/reviewers, Palomar, arXiv or other external action without explicit owner authorisation. Avoid model/vendor names in repository files.
